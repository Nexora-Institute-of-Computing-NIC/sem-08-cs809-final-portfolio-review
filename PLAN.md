# CS809 — Final Portfolio Review — PLAN

**Semester:** 8 · **Credits:** 1 · **Level:** Professional
**Theory:** 0 hrs · **Lab:** 30 hrs · **Tools:** GitHub, your live portfolio site, LinkedIn, a demo recording

## Course Format
The exit gate of the programme. Every student submits a complete, honest, professional portfolio and defends it to a small panel. This is the artefact that will represent the graduate to employers, collaborators, and clients for years.

## Objectives

1. Consolidate every meaningful project from 8 semesters into a coherent portfolio.
2. Build a live portfolio site that will outlast graduation.
3. Produce a 5-minute demo reel showing your best work.
4. Defend the portfolio in front of a panel — answer "what did you actually build?" honestly.
5. Set up the maintenance plan so the portfolio stays current.

## The Portfolio Must Contain

### 1. A Live Portfolio Site
- Hosted at `<username>.github.io` or a custom domain
- Fast, accessible, mobile-friendly
- Sections: Home, Projects, About, Writing (optional), Contact

### 2. Three Flagship Projects
Each written up with:
- **Problem** — what needed solving, and why
- **Approach** — technical decisions and trade-offs
- **Result** — working link or demo, with honest scope
- **What I learned** — one thing you would do differently
- **Code link** — GitHub repo, with a clean README

### 3. Public Presence
- **GitHub profile README** — polished, current, linked to the site
- **LinkedIn** — updated, consistent with the site
- **One public piece of writing** — a blog post, talk, or in-depth README
- **Open-source contributions** — at least 3 merged PRs linked from the site (from CS707 or elsewhere)

### 4. Demo Reel
- **5-minute recorded video** walking through your three flagship projects
- Voiceover, screen capture, clean cuts
- Not an advertisement — a real walkthrough

### 5. Maintenance Plan
- **Monthly:** add or update one project
- **Quarterly:** re-read the site and cut stale claims
- **Yearly:** full review and update
- **Every 3 years:** redesign

## Weekly Schedule (15 weeks)

1. **Audit** — inventory every project from semesters 1–8
2. **Rank** — score each project on depth, impact, and how proud you are
3. **Select** — pick the top 3 flagship projects
4. **Write** — project 1 (problem, approach, result, lesson)
5. **Write** — project 2
6. **Write** — project 3
7. **Build** — site skeleton (home, projects, about, contact)
8. **Build** — project pages, styling, accessibility pass
9. **Deploy** — GitHub Pages or custom domain, HTTPS
10. **GitHub profile** — update README and pinned repos
11. **LinkedIn** — update to match the site
12. **Record** — demo reel, first version
13. **Critique** — get feedback from a peer, supervisor, and one external person
14. **Revise** — incorporate feedback, second version of demo reel
15. **Defend** — panel review and submission

## The Panel

The final defence is with three people:
- The programme supervisor
- One NIC faculty member
- One external reviewer (industry, alumni, or a peer from another institution)

Format: 15-minute walkthrough by the student, 15-minute Q&A. The panel can ask anything: "why this architecture?", "what broke?", "what would you do with 6 more months?", "who is this project actually for?".

| Three flagship project write-ups (rigour, honesty) | 30% |
| Demo reel (5 minutes, clear, real) | 15% |
| Public presence (GitHub, LinkedIn, writing, PRs) | 15% |
| Panel defence | 15% |

## Honesty Rules

- **No inflated claims.** Every project listed must be one you actually built and can defend.
- **No dead links.** Audit before submission.
- **No private work as a public exhibit** unless explicitly permitted by the employer or client — and say so in the write-up.
- **No AI-generated write-ups.** The portfolio is the graduate's voice. AI tools may be used to refine, but every sentence must be yours and defensible.

## After the Defence

Graduation is not the end of the portfolio — it is the start of its real use.

- Respond to every message that comes through the contact form within a week.
- Say yes to at least one mentee per year.
- Update the site within one month of any new significant project.
- Come back to NIC each year to share what you learned after the programme.

The portfolio is not a static artefact. It is a living record of what the graduate has done — and it is the beginning of a long relationship with the community that helped build it.

## Final Word

Nexora Institute of Computing does not award degrees. It awards something else: a **public record of work**, a **habit of learning**, and a **community of people who know what you can do**.

CS809 is where the graduate makes that record visible — and where the institution's promise becomes real.
